# try 与 main 临时整合结果

仅在 integration/try-main-20261117 整合，未修改远程 main。恢复点为本地标签 backup-before-try-20261117，包含原 main 和本机 DeepSeek 配置支持（无真实密钥）。

## 保留与冲突处理

- 主页面冲突采用 try 的 BudgetForm、LedgerChat 组件化流程，替换原单一月度总预算表单。
- 保留 main 的 Nginx 部署配置、文档及八项分类修正。
- 保留本机 AI_API_KEY / DEEPSEEK_API_KEY 读取、可覆盖地址和模型、缺 Key 提示及隐藏输入启动脚本。
- 原来 localhost:80 的 Nginx 静态文件、正在运行的旧后端和原数据库均未替换。

## 已验证

- Vite 生产构建成功。
- Spring Boot 使用18082端口、data/merge-integration独立H2测试库实际启动。
- 全局默认总预算/分类预算、未独立设置月份的继承、指定月份覆盖、修改默认不影响独立月份、恢复默认。
- 真实账单新增、查询、删除及范围统计；超支金额计算。
- 相同 actionId 的对话入账请求只保存一次，重复调用返回同一账单ID。
- 浏览器设置页面保存预算并从真实后端读取。
- 演示模式的对话记账、会话历史刷新保留，无浏览器页面异常。

## 尚未验证与行为变化

- 新版真实DeepSeek多轮解析和小票OCR尚未验证：临时测试后端没有配置真实Key。不能将演示规则对话测试等同于真实模型验证。
- try中的文字记账信息完整时直接入账，小票仍要求确认。这与原版文字草稿也需确认的交互不同，正式合并前需确定是否接受。
- 顶部“记一笔”跳转AI助手，旧版手动录入弹窗已被移除，需要手动记账入口时应补回。
- 浏览器历史保存在本机localStorage，不是账号跨设备同步。

以上是临时整合结果，不代表已发布或所有AI路径完成验收。建议先确认文字入账/手动入口的产品行为，再进行真实模型验收，最后以PR合回main。
